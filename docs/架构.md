# DSh Open 架构说明（M1）

这份文档写给"三个月后的自己"：要加功能时先看这里，别再去翻代码找约定。

---

## 一、分层

```
┌──────────────── 界面（渲染进程）────────────────┐
│ index.html / style.css / i18n.js / app.js      │
│ pages/*.js  —— 每个页面一个文件                │
└───────────────────────┬────────────────────────┘
                        │ window.dsh（只有白名单方法）
┌───────────────────────┴────────────────────────┐
│ preload.js  —— 唯一的桥                         │
└───────────────────────┬────────────────────────┘
                        │ IPC（core/ipc.js 登记）
┌───────────────────────┴────────────────────────┐
│ 内核（主进程）                                  │
│ paths / logger / settings / db / registry      │
│ plugins / autolaunch                           │
└───────────────────────┬────────────────────────┘
                        │ 插件自己 require
┌───────────────────────┴────────────────────────┐
│ plugins/<id>/  —— 每个插件一个文件夹            │
└────────────────────────────────────────────────┘
```

规矩：**插件可以调内核，内核不认识插件**。内核里出现 `if (pluginId === 'qq')` 就是写错了。

## 二、要加东西时改哪里

| 想加什么 | 改这里 |
| --- | --- |
| 一个内置页面 | `main.js` 的 `registerBuiltinPages()` 加一条 + `renderer/pages/<id>.js` 加文件 + `index.html` 加 `<script>` + `i18n.js` 加文案 |
| 一个通道（QQ / B 站） | 写成插件，`ctx.registerChannel(...)` |
| 一个设置项 | `core/settings.js` 的 `DEFAULTS` 加字段（读的时候自动补默认值，不用迁移） |
| 一个界面能调的能力 | `core/ipc.js` 加 `handle()` + `preload.js` 加一行 |
| 一个数据库表 | `core/db.js` 的 `init()` 里 `CREATE TABLE IF NOT EXISTS` |
| 一种语言 | `core/settings.js` 的 `LOCALES` + `renderer/i18n.js` 的 `DICT` 加整套文案（下拉框自动多一项） |
| 一种插件权限 | `core/permissions.js` 的 `LIST` 加一条 + `renderer/i18n.js` 补 `perm.<id>.*`（权限说明弹窗自动多一行） |
| 标题右边的小按钮 | 页面里调 `ctx.setActions([...])`（每次渲染自动清空） |
| 一个弹窗 | 页面里调 `ctx.openModal({ title, desc, body })`（窗口内浮层，不是新开界面） |

## 三、路径约定（core/paths.js）

全部路径都从 `process.execPath` 反推，所以整个 `DSh Open` 文件夹搬到别的盘也能跑：

```
ROOT   = <软件目录>            D:\DSh Open
app    = ROOT\app（源码）/ ROOT\runtime\resources\app（运行时）
data   = <软件目录>\data      D:\DSh Open\data
cache  = <软件目录>\cache     D:\DSh Open\cache
plugins= ROOT\plugins
```

`ROOT` 的判定：`process.execPath` 是 `...\runtime\DShOpen.exe`，往上两级就是软件目录；如果不像这个结构则兜底 `D:\DSh Open`。

**不要在任何地方手拼路径**，一律 `require('./paths')`。

## 四、设置（core/settings.js）

- 文件：`D:\DSh Open\data\settings.json`
- 读取时永远和 `DEFAULTS` 深合并，老文件缺字段自动补 —— 所以**加字段永远不用写迁移脚本**。
- 写文件用"临时文件 + rename"，断电也不会写坏。
- 文件坏了不会崩：先备份成 `.broken-<时间戳>` 再回退默认值。

结构：

```json
{
  "schema": 1,
  "general": { "language": "zh-CN", "startOnBoot": false },
  "window":  { "width": 1200, "height": 780, "maximized": false },
  "ui":      { "lastPage": "dashboard" },
  "plugins": { "enabled": [], "disabled": [] }
}
```

插件开关为什么分两个列表：`enabledByDefault: true` 的插件启停记在 `disabled` 里，反之记在 `enabled` 里 —— 这样插件作者改默认值也不会把用户的设置冲掉。

## 五、存储（core/db.js）

优先用 Electron 内置的 `node:sqlite`（不需要装任何东西）。拿不到就自动退化成 `db-fallback.json`（`db.backend` 会告诉你是哪种）。

已有的表（只加不改）：

```sql
meta(key, value)
conversations(id, channel, account, title, kind, avatar, updated_at)
messages(id, channel, account, conversation_id, sender_id, sender_name,
         content, raw, role, created_at)
index idx_messages_conv on messages(conversation_id, created_at desc)
```

`channel` 字段就是区分平台的唯一依据（`qq` / `bili` …），以后加平台不用改表。

## 六、登记处（core/registry.js）

本体和插件都往同一个地方登记，界面只读登记结果：

```js
registry.addPage({ id, title, titleKey, icon, group: 'work'|'system', order, source, kind: 'builtin'|'plugin', hidden, showInNav })
registry.addChannel({ id, name, icon, status, source, meta })
registry.addTool({ id, name })
```

侧栏是遍历 `pages` 画出来的。
`id` 冲突时只警告、不覆盖（防止插件顶掉内置页面）。

`hidden: true` = 页面存在、能路由过去，但**不在侧栏显示**。设置页就是这么做的：它从右下角的小齿轮进入（`index.html` 里的 `#cornerSettings`，点击 `navigate('settings')`，打开时齿轮变蓝）。

**插件页面进侧栏的规则**（`renderer/app.js` 的 `isNavVisible()`）：
插件登记了页面，但**界面实现还不存在**（`window.DSHPages[id]` 没定义）时，侧栏不显示 —— 否则会多出一个"点进去不知道是干嘛的"空入口。
等 M2 做完插件界面机制，插件带上自己的 `renderer.js` 后入口会自动出现；要强行显示可以传 `showInNav: true`。
当前示例插件因此不登记页面（`plugins/sample-hello/index.js` 里是注释掉的样板）。

## 七、插件（core/plugins.js）

目录：`D:\DSh Open\plugins\<插件id>\`

`plugin.json`：

```json
{
  "id": "sample-hello",
  "name": "示例插件",
  "version": "0.1.0",
  "description": "一句话说明",
  "author": "作者",
  "main": "index.js",
  "permission": "client",
  "enabledByDefault": false
}
```

### 权限（`core/permissions.js`）

一个插件只选一种权限。它**不是安全开关**，而是决定插件「默认挂到哪个模块上」。
写错或不写一律按 `default` 处理（只记一条警告，不影响加载）。

| 权限 id | 徽标 | 名称 | 默认挂到 |
| --- | --- | --- | --- |
| `personality` | PC | 人格修正 | 人格管理 |
| `client` | Cli | 客户端 | 客户端本身 |
| `default` | Def | 默认 | 不挂载 |
| `memory` | Mem | 记忆 | 记忆管理 |
| `sticker` | Stk | 表情包 | 表情包管理 |
| `channel` | Chn | 通道 | 通道 |
| `tool` | Tool | 工具 | 模型工具 |
| `data` | Data | 数据 | 本地数据 |

插件里调 `ctx.expose(api)` 就会按权限自动挂到对应模块（PC → `personality`，Cli → `client`……），
也可以用 `ctx.expose(api, '模块名')` 显式指定。模块侧用 `registry.getModule('personality')` 取用 —— M4 做模型层时就是这么接。
中文名/说明/例子/英文原名在 `renderer/i18n.js` 的 `perm.*` 里；界面上的「权限说明」弹窗直接读这份清单（`app:info` 里的 `permissions`）。

**弹窗里的顺序**（`renderer/pages/plugins.js` 的 `sortPerms`）：`default` 永远排最后，其余按徽标首字母排、
首字母相同就比第二位 —— 于是显示成 Chn、Cli、Data、Mem、PC、Stk、Tool、Def。中文界面里名字后面补英文原名，
形如「人格修正（Personality correction）」（`permName`，文案是 `perm.<id>.en`）。

**插件卡片上的归属显示**（设置项 `ui.verbosePermission`，默认 `false`）：
- 关（默认）：`作者: X` + 约 5 个空格 + `权限: [Cli]`（间隔是 `.meta-gap`，17px） —— 一个徽标，鼠标悬停才出全称。
- 开：`作者: X` + 间隔 + `归属: 客户端 → 客户端本身`。
开关放在「权限说明」弹窗最下面（`buildVerboseSwitch`），改了立刻写进 `settings.json` 并重画页面。

### 插件卡片的「管理」菜单（右下角三个点）

每行插件卡片右侧底部有一个三点按钮（`.dots-btn`，竖排三个圆点），点开是 `openMenu()` 弹出的小菜单
（`renderer/app.js`，全局通用，别处也能用；`{ sep: true }` 是分隔线，`danger: true` 是红字）：

| 菜单项 | 做什么 |
| --- | --- |
| 打开插件目录 | `shell:openPath` 打开这个插件自己的文件夹 |
| 重新加载 | `plugins:reload` 全量重扫 |
| 删除插件（红字） | 弹确认框 → `plugins:remove` |

删除走 `plugins.remove(id)`（`core/plugins.js`），依次做四件事：
1. 校验目标文件夹必须是 `plugins\` 的**直接子目录**（用 `path.relative` 判断，越界一律拒绝）；
2. `deactivate()` 卸载插件、清掉 `require` 缓存；
3. `fs.rmSync(dir, { recursive: true, force: true, maxRetries: 3 })` 删插件文件夹，再删 `<data>\plugin-data\<id>`；
4. `settings.forgetPlugin(id)` 清掉启停记录 → `scan()` 重扫。

清单坏掉的插件（records 里键是 `!id`）也能删 —— `remove()` 会同时尝试 `records.get('!' + id)`。
另外 `readManifest` 会先剥掉 UTF-8 BOM（Windows 记事本存的文件常带 BOM，否则 `JSON.parse` 直接失败）。

`index.js`：

```js
exports.activate = function (ctx) {
  // 加页面（M2 之后插件能带界面时，侧栏才会出现这一项）
  ctx.registerPage({ id: 'xxx', title: '标题', icon: '✦', group: 'work', order: 200 });
  ctx.registerChannel({ id: 'qq', name: 'QQ', icon: '🐧' });
  ctx.expose({ ... });              // 按权限自动挂到默认模块
  ctx.settings.patch({ ... });      // 存在 settings.json 的 pluginSettings.<id> 下
  ctx.log.info('...');              // 写同一个日志文件
};
exports.deactivate = function () {}; // 可选
```

`ctx` 上有的东西：`id / manifest / dir / dataDir / permission / target / log / registerPage / registerChannel / registerTool / expose / settings.get / settings.patch`。

- 插件目录不存在、清单写错、入口抛异常，都**只会让这个插件变成 error 状态**，本体照常启动。
- 插件 id 规则：`^[a-z0-9][a-z0-9._-]{1,63}$`。
- 热重载会清掉 `require.cache`，所以改完插件代码点「重新扫描」就生效。

## 八、IPC 白名单（core/ipc.js）

| 通道 | 作用 |
| --- | --- |
| `app:info` | 版本、运行时、路径、设置、页面、通道、插件后端类型 |

## 九、渲染层约定

- `index.html` 用 **classic script**，不能用 ES module（`file://` 下会被 CORS 拦）。
- 页面模块的契约：

```js
window.DSHPages['<页面id>'] = {
  render(root, ctx) { /* 往 root 里 append 节点 */ },
};
```

`ctx` = `{ h, t, toast, state, dsh, navigate, refresh }`。

- `h(tag, props, ...children)`：`class` / `text` / `dataset` / `style`（对象）/ `onXxx` / 其余走 `setAttribute`。
- 文案一律 `t('key')`，不写死中文。
- 页面渲染抛异常不会白屏：`renderCurrent()` 会捕获并显示错误信息，同时写进日志。

## 十、构建（tools/build.ps1）

1. 关掉正在运行的 DShOpen
2. `robocopy app runtime\resources\app /MIR`（**会删除目标里多余的文件**，所以别手改 `runtime\resources\app`）
3. 建 `D:\DSh Open\data`、`D:\DSh Open\cache`、`plugins`
4. 把 app\assets\app-icon.ico 写进 exe 内嵌图标（tools\set-exe-icon.ps1），再重建桌面快捷方式

两个必须记住的坑：

- `build.ps1` **必须存成 UTF-8 带 BOM**，否则 Windows PowerShell 5.1 按 GBK 解析中文会直接语法错误。
- 在本会话的 shell 里启动 Electron 前必须 `Remove-Item Env:\ELECTRON_RUN_AS_NODE`（DSH 注入的环境变量会让 electron.exe 当 Node 跑、不出窗口）。从资源管理器双击没有这个问题，`启动.bat` 里也做了兜底。

## 0.3.0 新增模块

| 文件 | 干什么 | 对外 API |
| --- | --- | --- |
| `core/ai.js` | 大模型接入（OpenAI 兼容） | `overview() / get(id) / save(id,patch) / setActive(id) / test(id) / chat(id,msgs) / embed(id,inputs) / keyOf(id)` |
| `core/personas.js` | 人格：内置 6 套 + 玩家改动 | `all() / save(item) / remove(id) / setActive(id) / promptOf(id)` |
| `core/memory.js` | 记忆（SQLite + 可选向量） | `stats() / add(text,tags) / list() / search(q,k) / remove(id) / clear()` |
| `core/qq.js` | OneBot v11 客户端 | `status() / config() / saveConfig() / connect() / disconnect() / call() / sendPrivate() / sendGroup() / friends() / groups() / launchNapCat() / onEvent(fn)` |

### 约定（加新东西照着来）

- **接入层只认 OpenAI 形状**：`GET /models`、`POST /chat/completions`、`POST /embeddings`。以后接别家只要能对齐这三条，加一个 PRESET 就行，不用改调用代码。
- **Key 绝不给渲染进程**：`ai.get()` 只返回 `hasKey / apiKeyMasked`，真 Key 用 `ai.keyOf(id)` 只在主进程用。
- **记忆存本地**：`memories` 表（id/text/tags/vector/created_at）。选 ollama / siliconflow 只是拿向量，存储位置不变。
- **人格不必建表**：存 `settings.personas.items`，只存"改过的"和"自建的"，内置预设永远在代码里，删了 settings 就回到出厂状态。
- **QQ 状态推送**：`qq.onEvent(fn)` → 主进程 `win.webContents.send('qq:event', payload)` → 渲染层 `dsh.qq.onEvent(handler)`。
- **异步页面**：`render(root, ctx)` 可以 `async`。await 之后先 `if (!ctx.alive()) return;` 再往 DOM 里塞，否则切页时会重复渲染（app.js 每次渲染会换 `state.renderToken`）。

### 新增 IPC

`model:overview|save|setActive|test`、`personas:all|save|remove|setActive|preview`、
`memory:stats|list|add|search|remove|clear`、
`qq:status|config|save|connect|disconnect|sendPrivate|sendGroup|friends|groups|launchNapCat|pickNapCat`。

## 0.4.0 追加：收件箱 / 自动回复 / 表情包

### 新模块（`app/core/`）

| 文件 | 干什么 |
| --- | --- |
| `inbox.js` | 收件箱读写。会话 id 约定：群 = `group:<群号>`，私聊 = `user:QQ号`；消息正文在 `messages.content`，`role` 区分 `user`（对方）和 `assistant`（自己/模型）。 |

- `pages/stickers.js`：情绪筛选 + 网格 + 详情弹窗（可直接选会话发送）。

- 表情图片走 `file:///`，所以 `index.html` 的 CSP `img-src` 必须带 `file:`。
- 自动回复默认关；开关只在「通道」页，配置存在 `settings.autoreply`。
- 新增通道（比如 B 站）只需往 `inbox` 里写，不用改页面。

### 新增 IPC

`inbox:conversations|messages|stats|send`、`stickers:stats|list|rescan|setSource|pick|send`、`autoreply:config|save`。

## 0.6.0 追加：节流 / 关系 / 自动记忆

### 新模块（`app/core/`）

| 文件 | 干什么 |
| --- | --- |
| `bond.js` | 关系。表 `bonds(user_id PK, name, score, mood, wish, mood_date, updated_at)`。好感 0~100 分五档（陌生/眼熟/朋友/要好/亲密）；`MOODS` 是 12 条固定池，每天抽一次（不调模型、不花钱）。`describe()` 生成一段"你和 X 的关系 + 今天的状态"，直接拼进 system。 |
| `distill.js` | 自动记忆。每轮聊完把「对方说的话 + 回答」丢给 `qwen2.5:0.5b`，让它只挑稳定的信息（喜好/习惯/身份/约定）存进 `memories`。**必须保留逐行兜底解析**：0.5b 经常不写 JSON，只给一行一句话。 |

### 改动的模块

- `autoreply.js` 整篇重写，加了三道刹车：白名单（`allowedUsers` 为空 = 谁都不回）、同一会话最小间隔（`minGapSec`）、每分钟上限（`maxPerMinute`，超了丢弃不排队）。群消息还要过 `groupAtOnly`（只有 `@` 才回，`atme` 或 `raw_message` 里出现 `[CQ:at,qq=<selfId>]`）。回答前有 `humanDelay()` 拟人停顿。
- `proactive.js` 的 `compose()` 拼上 `bond.describe()`，发送成功后 `bond.bump()`。
- `settings.js` 新增 `autoreply.{scope,groupAtOnly,minGapSec,maxPerMinute,typingDelay}`、`bond.{enabled,perMessage,perReply,perProactive}`、`model.memory.distill.{enabled,model,maxItems}`。

### 约定（踩过的坑）

- 模块级函数要显式挂到导出对象上。`bond.ensure` 漏挂导致 `whenReady` 里抛 `TypeError`，**后面整段启动代码（`proactive.start()` 等）直接被跳过**，日志里只会看到一行 UNHANDLED。加异常时务必确认它不会打断启动链。
- 小模型（0.5b）不可信：JSON 解析失败要有逐行兜底，否则永远拿到空数组。
- `h()` 里 `value` 走 `setAttribute`，对 `<textarea>`/`<select>` 无效，已在 `app.js` 里特判直接赋 `el.value`。

### 新增 IPC

`bond:get|list|reset|roll|save`、`distill:config|save|try`。

## 0.7.0 追加：表情包管理

### 数据放在哪

- `stickers.json`（缓存）：扫出来的清单，删掉会自动重建。
- `stickers-overrides.json`（**玩家的手工改动**）：`{ "<文件绝对路径>": { emotion?: "开心", favorite?: true } }`。重扫不会丢，因为扫描时是「先按文件名猜、再拿 overrides 覆盖」。
- `stickers-trash/<时间戳>/`：删除 = 把文件 **rename 到这里**，不是 `rm`。后悔了手动搬回去就行。

## 0.8.0 追加：表情配图规则（core/stickerRules.js）

一句话分工：**表情包页管「哪张图算哪个情绪」，stickerRules 管「什么时候用哪一组」**。

调用方：
- `core/autoreply.js`：`respond()` 里按**她自己回出来的那句话**判情绪（不是按用户说的），概率 `cfg().chance`。
- `core/proactive.js`：同样用 `pickFor(text)`，概率 `Math.max(0.35, chance)`（主动找她说话时更愿意带图）。

界面：`renderer/pages/model.js` 第 4 块 —— 开关、概率、10 行规则表（`.rule-row`：emoji+情绪 / 关键词提示 / 分组下拉 / 有图徽标）、「挑一张看看」结果卡（`.try-card`）。
